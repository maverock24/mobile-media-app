## Q24

The visible sub-tab is derived, not stored: `musicSubTab = $derived<MusicSubTab>(youtubePanel.open ? 'youtube' : mediaEngine.activeMusicDeck)` (`src/routes/+page.svelte:52-55`), where `MusicSubTab = 'A' | 'B' | 'youtube'` (`:52`). `selectMusicSubTab` early-returns when the tab is already current, opens the YouTube panel for `'youtube'`, and otherwise assigns `mediaEngine.activeMusicDeck = tab` plus `closeYoutubePanel()` (`:57-65`).

`activeMusicDeck` is typed `'A' | 'B'` with default `'A'` (`src/lib/stores/mediaEngine.svelte.ts:124`, `:193`). Its only writers are `+page.svelte:62` and two unit tests (`tests/unit/stores/mediaEngine.test.ts:150`, `:179`); no store setter exists, and `MiniPlayer.svelte:461` only reads it, to decide whether to render the Deck B volume slider.

So the existing third, non-deck tab works because it owns a separate flag (`export const youtubePanel = $state({ open: false, ... })`, `src/lib/stores/youtubePanel.svelte.ts:11-16`) that wins by precedence inside the derivation. A `pairs` tab therefore needs either a widened `activeMusicDeck` (which also feeds `MiniPlayer.svelte:461` and the derivation) or a second precedence flag, and with two such flags the precedence between them is currently undefined. One more break: `selectMusicSubTab`'s else branch closes the YouTube panel only for the two deck values (`+page.svelte:63`), so a `pairs` branch that skips that call leaves `youtubePanel.open` true and the derivation keeps returning `'youtube'`.

## Q25

Both decks sit in the music wrapper `<div class="absolute inset-0 overflow-hidden flex flex-col" class:hidden={activeTab !== 'music'}>` (`src/routes/+page.svelte:206`), each in its own `<div class="absolute inset-0" class:hidden={musicSubTab !== 'A'}>` (`:231-236`). The wrapper comment states the contract (`:196-205`): `class:hidden` is `display:none` and does **not** pause audio. Nothing unmounts, so each deck's component instance and every `$effect` in it keep running while hidden, including the always-push effect and the transport claim (`src/lib/components/views/Mp3PlayerView.svelte:615-689`, progress push at `:695-709`). Audio is untouched because the element is created detached by the player module (`audio = opts.createAudio ? opts.createAudio() : new Audio()`, `src/lib/audio/player.svelte.ts:146`), not rendered in the hidden DOM.

Props on the way in are minimal: `let { deck = 'A' as 'A' | 'B', activeTab = 'music' as string } = $props()` (`Mp3PlayerView.svelte:103`), rendered as `<Mp3PlayerView deck="A" {activeTab} />` (`+page.svelte:232`, `:235`). `YoutubePanel` gets no props at all (`+page.svelte:248`), self-gates on `{#if youtubePanel.open}` (`src/lib/components/ui/YoutubePanel.svelte:554`) and deliberately keeps its `<audio>` outside that gate (`:10`, tag at `:531`). Only weather and settings are `{#if}`-mounted (`+page.svelte:257-266`), so music, podcast and radio panels all persist.

A `pairs` panel placed alongside them is therefore always mounted and would be the third always-alive child of the music content area. The house style for such a screen, from `RadioView.svelte`: no props at all (`<RadioView />`, `+page.svelte:255`), local `$state` (`src/lib/components/views/RadioView.svelte:13-22`), `$effect` for `registerAudioSource` and engine callbacks (`:33-40`, `:42-61`), a root `<div class="flex flex-col h-full bg-background/85">` (`:220`), its own inner tab bar of plain buttons with local state (`:222-243`), an explicit empty state (`:248-254`), and `<ul class="divide-y">` rows with `list-row-surface`, truncating `<p>`s and `aria-label`ed icon buttons (`:255-290`). Toasts go through `addToast({ message, type, autoDismissMs })` (`src/lib/stores/toastStore.svelte.ts:24-31`), used for example at `Mp3PlayerView.svelte:1060` (note `RadioView.svelte:8` imports `addToast` but never calls it).

## Q26

The shell publishes one string through an effect: `mediaEngine.activeView = activeTab === 'music' ? \`music:${musicSubTab}\` : activeTab` (`src/routes/+page.svelte:69-72`). `ActiveView` is exactly `'music:A' | 'music:B' | 'music:youtube' | 'podcasts' | 'radio' | 'weather' | 'settings'` (`src/lib/stores/mediaEngine.svelte.ts:56-65`).

`activeView` has a single reader in `src/`: the `displayedSource` getter (`mediaEngine.svelte.ts:212`). That getter feeds everything downstream: `MiniPlayer.svelte:35`, and each source's self-gate (`Mp3PlayerView.svelte:616`, `:731`, `YoutubePanel.svelte:132`, `PodcastView.svelte:332`, `RadioView.svelte:72`).

A `pairs` tab would have to publish `'music:pairs'`, which `ActiveView` does not contain, so the assignment at `+page.svelte:71` fails typecheck (`musicSubTab` is the template-literal operand). If the union were widened, the mapping at `mediaEngine.svelte.ts:213-219` falls through to `: null`, and then: `:228` is skipped, `primary` is `null` for music (`:230-235`), the "keep the watched deck while paused" branch at `:240` cannot fire (`viewSource` is `null`), the loop at `:244-246` returns the first playing source in the order youtube, A, B, podcast, radio, and otherwise `:248` returns `null`, which makes `MiniPlayer` take its `'global'` path (`MiniPlayer.svelte:34-35`). The tie-break is already pinned by a test: `tests/unit/stores/mediaEngine.test.ts:192-198` (`prefers Deck A over Deck B on a non-music tab when both decks play`).

## Q27

The deck's transport claim does not depend on its sub-tab being visible; it depends on `displayedSource`: `const isMusicView = mediaEngine.displayedSource === (deck === 'A' ? 'A' : 'B')` (`src/lib/components/views/Mp3PlayerView.svelte:616`, repeated at `:731`), then `if (isMusicView) claimMusicControls()` (`:668`, `:739`). Both decks are always mounted, so these effects re-run whenever `displayedSource` changes.

`claimMusicControls` (`Mp3PlayerView.svelte:592-608`) calls `setPlaybackHandlers` / `setSkipHandlers`, which overwrite single `_onPlay/_onPause/_onSeek/_onNext/_onPrev` slots with no owner check (`mediaEngine.svelte.ts:320-329`). Only the deck matching `displayedSource` claims, so on a `pairs` tab exactly one deck holds the MiniPlayer transport, picked by playback per Q26. The consequence to note: with `viewSource === null`, the keep-the-paused-deck branch (`mediaEngine.svelte.ts:240`) cannot fire, so a paused deck on the pairs tab is not reachable from the MiniPlayer's play button; the button reads `_onPlay` (`MiniPlayer.svelte:181-187`).

MediaSession is engine-owned: three effects read `mediaEngine.item`, `isPlaying`, `duration` and `currentTime` (`mediaEngine.svelte.ts:561-591`). A deck writes those globals only under `if (isMusicView && musicOwnsDisplay)` (`Mp3PlayerView.svelte:672-686`), where `musicOwnsDisplay` excludes podcast, radio, youtube and mixer. So on a pairs tab the lock-screen metadata follows the playing deck while no other source plays, and follows that other source otherwise.

## Q28

The sub-tab bar is `<div class="flex shrink-0 border-b ..." role="tablist" aria-label="Music player">` (`src/routes/+page.svelte:208`) with three `role="tab"` buttons carrying `aria-selected={musicSubTab === 'A' | 'B' | 'youtube'}` (`:210-214`, `:216-220`, `:222-226`). No `aria-controls`, no `id`, no `role="tabpanel"`, no roving `tabindex`; the accessible name is the text content, `A`, `B`, and icon plus `YouTube`. The same `aria-label="Music player"` is also on the deck's player region (`Mp3PlayerView.svelte:2182`), which is why the E2E helper uses CSS rather than roles (`tests/e2e/music-player.test.ts:52-56`). The bottom nav is a second `role="tablist"` with `aria-label="Navigation"` (`+page.svelte:278`), whose buttons carry `aria-label={tab.label}` (`:285`) and `aria-selected` as a string (`:284`).

E2E addresses sub-tabs by exact name everywhere: `page.getByRole('tab', { name: 'B', exact: true })` and `'A'` at `tests/e2e/music-player.test.ts:271`, `:333`, `:347`, `:351`, `:357`, `:364`, `:409`, `:422`, `:446`, `:539`, `:569`, `:576`; `'YouTube'` at `tests/e2e/smoke.test.ts:91-92`; `goToTab` does the same for bottom-nav labels and asserts `aria-selected` (`tests/e2e/helpers.ts:26-40`). Because `getByRole` is page-wide and both tablists carry `role="tab"`, a new button's accessible name must be unique across both tablists: `'Pairs'` is safe, anything colliding with `'A'`, `'B'`, `'Music'`, `'Podcasts'`, `'Radio'`, `'Weather'` or `'Settings'` would make existing locators strict-mode ambiguous.

## Q38

`tests/unit/models/player.test.ts` is the only unit suite over the player module: 610 lines, 13 `describe` blocks, 47 `it()` cases. Its seams are a hand-written `FakeAudio` element (`:6-36`) and `makePlayer` (`:38-53`), which injects `settings`, a mocked `resolveUrl` returning `blob:<name>`, `createAudio: () => audio`, and `native: false`; `flush()` is a 5 ms timeout (`:55`). Those are exactly the seams `createPlayer` documents (`src/lib/audio/player.svelte.ts:79-100`).

What constrains a new path:
- repeat-one / loop one track: `describe('player — repeat-one')` `:114-163` pins same-track rewind (`state.currentIndex` unchanged, `audio.currentTime` back to 0, `playCalls` risen) and pins that the live `isSelectionLoop()` getter beats the `selectionLoop` snapshot from `play()` (`:133-163`). `tests/unit/models/getNextTrackIndex.test.ts:42-60` pins single-track behaviour: stop with no flag, loop with `isRepeat`, `selectionLoop` as the wrapping flag.
- start at position: constrained by what does *not* exist. `PlayerQueueOptions` carries only `preserveOrder`/`selectionLoop` and `PlayerLoadOptions` adds only `startIndex`/`keepCurrent` (`player.svelte.ts:64-77`); `resume()` takes no position and, when the element has no `src`, restarts the selected track from the beginning (`:591-620`). `describe('player — stop and resume (cross-source exclusivity)')` `:432-502` asserts precisely that (`audio.src === ''` after `stop()`, `resume()` re-resolves and restarts). `seek` is only covered inside `:210-219` (`player.seek(42)` lands on element and state).
- queue-shape options that a pairing start would reuse: `:503-534` (`preserveOrder`, `onBeforeAdvance`).

## Q41

Nine tests in `test.describe('Music deck playback (player module)')`, `tests/e2e/music-player.test.ts:173-587`. Sub-tab wiring is pinned by: `:271` (click `B` before loading deck B's library), `:333`/`:347`/`:351` (A/B round trip keeps each deck's own title and file), `:357`/`:364` (the MiniPlayer's Next re-points at whichever deck's tab is open), `:373` (on the Podcasts tab the MiniPlayer shows Deck A while both play), `:569`/`:576` (the stop-the-displayed-deck case, both directions). Also `tests/e2e/smoke.test.ts:91-92` pins that the YouTube sub-tab is visible and clickable from the deck's file browser.

How the suite drives a deck: a folder enters through the hidden file input, via `page.waitForEvent('filechooser')` plus a scripted `.click()` on `input[type="file"][multiple]` (`:35-44`, and `:161-171` where deck B's picker is the third input because Deck A renders two); then rows are clicked by name (`Play Track One`) and assertions read the MiniPlayer (`:46`) or `expectDeckShows` (`:150-158`). Store state is seeded only through `page.addInitScript`, and the only key used anywhere in `tests/e2e` is `music-settings` with `{ isRepeat: true }` (`:233-235`, `:319-321`, `:396-398`, `:481-483`, `:531-533`).

A new sub-tab is reachable. Playwright runs the web build (`pnpm build && pnpm preview` on `http://127.0.0.1:4177`, `playwright.config.ts:40-42`, base URL used at `tests/e2e/helpers.ts:6`), the shell needs no Capacitor, and any new `role="tab"` button is addressable by name the same way `'B'` is (Q28). A seeded pairing follows the same shape: `page.addInitScript(() => localStorage.setItem('<pairing-key>', JSON.stringify(payload)))` before `page.goto('/')`. The payload can only hold serialisable references, which rules out the web variant of `StoredAudioFile` because it carries a live `File` (`src/lib/models/music.ts:17`), and points at the native/drive variants (`:18-26`) or a favourite-style record keyed by `getStoredFileKey` (`:134-138`, favourite union `:42-60`). Seeding does not create a library: the referenced files still have to be picked through the chooser in the same test, exactly as the nine deck tests do.

Two inherited constraints for a new panel: the helpers `playerView`, `visiblePlayerView` and `visibleDeckTitle` resolve `[role="region"][aria-label="Music player"]` and its `h2` (`music-player.test.ts:52-84`), so a pairs panel that reuses that aria-label, or renders a second *visible* deck region, makes `expectDeckShows` (`:150`, used by four tests) ambiguous; and `page.locator('audio')` is asserted at count 2 (`:194`, `:292`), so a panel must not add an `<audio>`.

## Q42

No test covers `persisted()` directly. There is no `persisted` test file under `tests/`, and grep across `tests/` finds no import of `$lib/persisted.svelte`; the only importer in the repo is `src/lib/stores/settings.svelte.ts:1`. `tests/unit/models/podcast-persist.test.ts` is named for persistence but exercises the store end-to-end through `podcastData`: a synchronous write of a new subscription and the `nextId` (`:13-40`), an older-build payload migrated on boot (`:42-58`), the `trim` bound on the stored blob (`:60-100`), and survival of a `QuotaExceededError` (`:102-140`).

So the generic contract is only covered incidentally: storage key and merge-over-defaults (`src/lib/persisted.svelte.ts:24-27`), the microtask-coalesced flush (`:69-77`), the `$effect.root` that reads each top-level key to establish reactivity (`:79-86`), and the pagehide/beforeunload/visibilitychange/pause flush listeners (`:100-110`). Nothing asserts the shallow top-level key tracking itself, and nothing asserts flush timing. A new pairing store would inherit the same blind spot unless a test for the module is added.

### Unresolved

- **Q24, precedence between two non-deck flags.** Today only `youtubePanel.open` exists, so there is no code that decides what happens when a second non-deck tab is open at once; the answer cannot be read off the current derivation (`+page.svelte:53-55`). Whether `pairs` gets its own store flag or widens `activeMusicDeck` is a Design decision, not a code fact.
- **Q26, whether `ActiveView` should carry `'music:pairs'` at all.** Both options are legal (`+page.svelte:71` plus the union at `mediaEngine.svelte.ts:56-65`), and the runtime behaviour of the widened option is only derivable, not tested: no existing test feeds an unknown view to `displayedSource` (`tests/unit/stores/mediaEngine.test.ts:145-201`).
- **Q41, a real seeded pairing round trip.** No pairing store exists yet, so the exact payload shape (its key, and whether it lives in `music-settings` or a new key) cannot be verified against code; only the seeding mechanism (Q41) and the serialisability limit (`src/lib/models/music.ts:17`) are confirmed.
